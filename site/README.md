# Sonora website

Plain static HTML and CSS, with no build step, no framework, no external fonts or scripts, and no tracking.
`.github/workflows/site.yml` publishes this folder to GitHub Pages on every push to `main` that touches `site/`.
The planned domain is **sonoradaw.com**: every page's canonical and Open Graph URLs already point there.

| File | What it is |
|---|---|
| `index.html` | Home: hero, alpha notice, what Sonora is (not a copy, familiar on purpose, made for new music), producer requests, collaboration, AI and agents, included instruments, updates, who it's for / not for, CTA |
| `features.html` | Everything that works today, by area, starting with collaboration, the assistant and the instruments |
| `compatibility.html` | Platforms, plug-in formats, opening Live 12 sets (possible, not the main use), native device status, the checkable comparison with Live 12 |
| `download.html` | Alpha warning, the four downloads (all link to GitHub Releases `latest`), requirements, updates (Sparkle deltas), channels, build from source |
| `faq.html` | About, the alpha, Live sets and sound, instruments, collaboration, AI and privacy, license |
| `about.html` | Why Sonora exists, the author's note, the author (with the CV link), how it's built |
| `community.html` | Ways to help, how to write a bug report, Discussions, contributing code, conduct |
| `assets/site.css`, `assets/site.js` | Shared styles (dark only); mobile menu and keyboard-accessible screenshot lightbox |
| `assets/brand/` | Copies of `resources/brand/` (generated by `tools/brand_render`) plus PNG sizes |
| `assets/img/` | WebP screenshots, all rendered by Sonora (see below), and `og.png` for link previews |
| `check_links.py` | Fails if a local link, image or `#anchor` is broken. CI runs it before deploying |
| `rename.sh` | `site/rename.sh NewName` swaps the product name in every page |

Every page repeats the same head, alpha strip, header and footer. When you change one of them, change all seven pages.

## Look at it locally

```bash
python3 -m http.server 8794 --directory site
```

Then open <http://localhost:8794/>. Opening `site/index.html` directly from disk also works.

## Publish (one time)

1. Repository Settings > Pages > Source: **GitHub Actions**.
2. Push to `main`. The site appears at `https://lordillusions.github.io/sonora/`.
3. Domain: add `sonoradaw.com` in Settings > Pages, add a `site/CNAME` file containing `sonoradaw.com` on one line,
   and point the domain's DNS at GitHub Pages.

## Updating content

- **Downloads:** every button links to `https://github.com/lordillusions/sonora/releases/latest/download/<stable name>`
  (`Sonora-macOS.dmg`, `Sonora-Windows-x64-setup.exe`, `Sonora-Linux-x86_64.AppImage`, `Sonora-Linux-amd64.deb`,
  `Sonora-Prism-VST3-macOS.pkg`): the installers workflow attaches these copies next to the versioned files. `site.js`
  reads the visitor's system from the browser (no request) and puts that card and button first.
- **Alpha status:** the strip at the top of every page, the notice on `index.html` and `download.html`, and the
  "The alpha" group in `faq.html`. Change all of them together when the status changes.
- **Discussions:** the Community page, FAQ and footer link to GitHub Discussions. Enable Discussions in the repository
  settings, or change those links.
- **About:** the "Read my CV" button links to https://cv.lordillusions.com/cv-photo/ (opens in a new tab).
- **Comparison with Live:** only facts that can be checked. No speed or sound-quality claims. Re-check the rows at each
  Live release and update the "Checked against ... in October 2026" notes on `index.html` and `compatibility.html`.
- **Device status:** `compatibility.html#devices` follows ROADMAP M2.
- **Claims:** describe only what is implemented (ROADMAP `[x]`). Collaboration over the internet needs a relay the user
  hosts until a public relay exists; Sonora Resynth is native only; Windows and Linux have no updater.
- **Trademarks:** nominative use only ("opens Ableton Live 12 sets"). Keep the footer notice on every page.

## Screenshots

All screenshots are Sonora's own UI drawn by `ui_snapshot` (never screenshots of Live). To regenerate, render with
`build/tools/ui_snapshot out.png <set> --scale 2 --size 1440x900 [--session] [--no-browser] [--prefs keys|updates]
[--monitor curve] [--collab share|host|guest|presence]`, crop, then `cwebp -q 86 -m 6 in.png -o site/assets/img/name.webp`.
The home page's animation is `assets/img/timelapse.webp`, made by `scripts/site/make_timelapse.py OUT` (the demo set built
stage by stage, rendered frame by frame, ~40 s; it also writes a GIF). Reduced-motion visitors get `hero-arrangement.webp`.

**Never use real projects.** The hero, Session, collaboration, FX-chain, Curve LFO and Prism shots come from a generated demo set:

```bash
python3 scripts/site/make_demo_set.py /tmp/sonora-demo
build/tools/ui_snapshot hero.png "/tmp/sonora-demo/Sonora Demo.xml" --scale 2 --size 1440x900 --no-browser --lane-height 34 --ppb 4 --track 6
```

Add `--session` for the Session view, `--collab host` for the Collaborate panel (`collab-panel.webp` is that panel
cropped) and `--collab presence` for remote cursors (`collab-presence.webp` is the top 1325 px). The script synthesizes
its own drum and FX samples, so no third-party sound or sample name appears.

Other sources: `fx-chain.webp` and `curve-lfo.webp` are the device rows of `--track 9` / `--track 10` (Lead: Echo, Delay, Reverb; Pad: Curve LFO) at 1900x900 and 1440x900, `prism.webp` is `--track 8 --wavetable-window`; `resynth.webp` is the device panel cropped
from `docs/screenshots/native-resynth.png` (a `resynth_probe --demo` set), `assistant.webp` is
`docs/screenshots/agent-control-native-llm.png`. `splash.webp` and `og.png` are the start-up window with its status
line removed; `og.png` adds the line "Free, open-source DAW for macOS" and "Alpha". Keep plug-in names and version
numbers out of screenshots.
