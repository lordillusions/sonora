Platforms

Where Sonora runs

The Mac is home. Windows and Linux builds exist, but they are even earlier than the Mac version.

PlatformStatusNotes
macOS 13 or later, Apple siliconMain platform (alpha)Metal drawing, VST3 and Audio Units, automatic delta updates, collaboration and the assistant.
macOS on IntelNot supportedThe graphics library Sonora uses is built for Apple silicon only.
Windows x64Early alpha buildInstaller built automatically and barely tested on real machines. The interface draws on the CPU, there are no automatic updates, and the installer isn't code-signed yet, so Windows will warn about an unknown publisher.
Linux x64Early alpha buildAppImage and .deb, tested by installing on Ubuntu 24.04 and starting the app. The interface draws on the CPU and there are no automatic updates. Audio hardware and plug-ins are not yet qualified.

Opening Live sets

Possible, but not the main idea.

Sonora can open sets saved by Ableton Live 12, edit them and save them back. That's handy for bringing an idea or a loop over. But Sonora is made for starting new music, and an existing set may sound different or be missing devices, so we don't recommend it as a way to keep working on finished Live projects.

Tested

Opening

A library of 65 real-world sets, from sketches to 50-track productions, opens on every build.

Tested

Saving

Untouched sets re-save to identical XML, and edited sets were checked by opening them in Live 12 again.

By design

Nothing is thrown away

Data Sonora doesn't understand stays in the file when you save. A load report lists everything Sonora skipped.

Sonora-only

Extras stay in Sonora

Linked clips, hidden or deactivated tracks and Sonora's own instruments are stored in a form Live ignores. Live opens the set, but doesn't play Sonora's instruments and drops these extras if it saves the set.

Sonora reads and writes the set format only. It doesn't use any part of Live, and you don't need Live installed. Samples from Live's own library are found only if that library is on your Mac.

Devices

Native device status

When a set uses a built-in device, Sonora runs its own implementation if it has one. These are original code: they may not sound identical to the device with the same name.

DeviceStatusNotes
EQ Eight, UtilityNativeComplete controls.
SimplerNativeClassic, 1-Shot and Slice modes, filter, LFO and envelopes.
Racks (Instrument, Drum, Audio Effect)NativeChains, key, velocity and chain-select zones, macros.
Reverb, DelayNativeComplete parameter sets.
Impulse, Echo, Compressor, Limiter, Auto FilterNative, earlyPlay back and edit.
Redux, Tuner, Gate, Auto PanNative, earlyFirst versions.
Arpeggiator, Note Length, VelocityNative, earlyMIDI effects run before the instrument.
Max for Live devicesNot supportedKept in the file and listed in the load report. A few common ones, such as a loudness meter, have a native stand-in.
Other built-in instruments and effectsNot yetKept in the file and listed in the load report. A missing instrument can play a placeholder sound so you still hear the part.

Where Live is ahead, by a lot

  • Maturity: a finished, polished product with years of documentation and professional support. Sonora is an alpha.
  • Max for Live and its huge ecosystem of devices.
  • The full set of built-in devices, and sound content in Packs.
  • Hardware integration such as Push, and Ableton Link.

If you're a professional, or you can afford it, buy Ableton Live. It's amazing software and you'll get support with it. Sonora is for everyone else, and for anyone who wants to help build something open.
